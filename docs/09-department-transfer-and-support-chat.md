# การย้ายแผนกและแชทแจ้งปัญหา

## การย้ายแผนก

ผู้บริหารและผู้ดูแลระบบเปิด **จัดการพนักงาน** เลือกบัญชี แล้วกด **ย้ายแผนก** ระบบให้ระบุแผนกใหม่ วันที่มีผล ตำแหน่งใหม่ และเหตุผล

เมื่อยืนยัน ระบบจะ:

1. ปิดช่วงเวลาสังกัดเดิมใน `employee_department_history`
2. เปิดช่วงเวลาสังกัดใหม่และเปลี่ยนแผนกหลักของบัญชี
3. ปรับสิทธิ์มองเห็นแผนกตามตัวเลือก โดยสามารถคงสิทธิ์แผนกเดิมไว้สำหรับงานข้ามทีม
4. บันทึกผู้ดำเนินการและรายละเอียดใน `access_audit`
5. คงงาน กิจกรรม ปัญหา และผล KPI เดิมไว้กับรหัสแผนกที่บันทึกในแต่ละรายการ จึงไม่เปลี่ยนข้อมูลย้อนหลัง

การแก้แผนกหลักจากฟอร์มสิทธิ์ทั่วไปถูกป้องกันไว้ เพื่อให้ทุกการย้ายมีประวัติ

## ระบบข้อความภายใน

เมนู **ข้อความ** รองรับห้องกลาง แชทส่วนตัว และกลุ่มที่เลือกสมาชิกได้ ข้อความใหม่แสดงผ่าน Supabase Realtime และเก็บชื่อกับแผนกของผู้ส่ง ณ เวลาที่ส่ง รูปและไฟล์แนบจัดเก็บใน Storage แบบ private และเปิดผ่าน signed URL เฉพาะสมาชิกในห้อง

- ห้องกลาง: บัญชี active ทุกคนอ่านและส่งได้
- แชทส่วนตัว: ผู้สร้างและผู้รับที่เลือกเท่านั้น
- กลุ่ม: ผู้สร้างและสมาชิกที่เลือกเท่านั้น
- ประเภทข้อความ: ข้อความ / แจ้งปัญหา / อัปเดตผล
- ไฟล์แนบ: รูปภาพ, PDF, Word, Excel, PowerPoint, ZIP และข้อความ ขนาดไม่เกิน 10 MB
- ผู้ใช้แก้ไขหรือลบข้อความไม่ได้ในเวอร์ชันนี้
- ห้ามส่งรหัสผ่านหรือข้อมูลลับที่ไม่เกี่ยวข้องกับงาน

## ขั้นตอนเปิดใช้

1. รัน migration `202610150039_department_transfers_and_support_chat.sql` และ `202610160040_chat_rooms_and_attachments.sql` ใน Supabase
2. ตรวจว่าตารางใหม่เปิด RLS และ `support_chat_messages` กับ `chat_rooms` อยู่ใน publication `supabase_realtime`
3. ทดสอบ Staff สร้างกลุ่มและแชทส่วนตัว แล้วตรวจว่าบัญชีนอกห้องอ่านไม่ได้
4. ทดสอบอัปโหลดรูปและไฟล์ ตรวจ signed URL และเพดาน 10 MB
5. ทดสอบบัญชี Admin/Exec ย้ายพนักงานหนึ่งคน แล้วตรวจประวัติ แผนกปัจจุบัน และข้อมูลย้อนหลัง
6. เมื่อผ่านจึงเผยแพร่ไฟล์หน้าเว็บเวอร์ชันนี้
