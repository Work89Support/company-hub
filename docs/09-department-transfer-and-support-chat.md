# การย้ายแผนกและแชทแจ้งปัญหา

## การย้ายแผนก

ผู้บริหารและผู้ดูแลระบบเปิด **จัดการพนักงาน** เลือกบัญชี แล้วกด **ย้ายแผนก** ระบบให้ระบุแผนกใหม่ วันที่มีผล ตำแหน่งใหม่ และเหตุผล

เมื่อยืนยัน ระบบจะ:

1. ปิดช่วงเวลาสังกัดเดิมใน `employee_department_history`
2. เปิดช่วงเวลาสังกัดใหม่และเปลี่ยนแผนกหลักของบัญชี
3. ปรับสิทธิ์มองเห็นแผนกตามตัวเลือก โดยสามารถคงสิทธิ์แผนกเดิมไว้สำหรับงานข้ามทีม
4. บันทึกผู้ดำเนินการและรายละเอียดใน `access_audit`
5. คงงาน กิจกรรม ปัญหา และผล KPI เดิมไว้กับรหัสแผนกที่บันทึกในแต่ละรายการ จึงไม่เปลี่ยนข้อมูลย้อนหลัง

การแก้แผนกหลักจากฟอร์มสิทธิ์ทั่วไปถูกป้องกันไว้ เพื่อให้ทุกการย้ายมีประวัติ

## ห้องแชทแจ้งปัญหา

เมนู **แชทแจ้งปัญหา** เป็นห้องกลางเวอร์ชันทดสอบ ผู้ใช้ active ทุกบทบาทอ่านและส่งข้อความได้ ข้อความใหม่แสดงผ่าน Supabase Realtime และเก็บชื่อกับแผนกของผู้ส่ง ณ เวลาที่ส่ง

- ประเภทข้อความ: แจ้งปัญหา / อัปเดตผล
- จำกัดความยาว 2,000 ตัวอักษร
- ผู้ใช้แก้ไขหรือลบข้อความไม่ได้ในเวอร์ชันทดสอบ
- ห้ามส่งรหัสผ่าน ข้อมูลลูกค้า หรือข้อมูลการเงิน

## ขั้นตอนเปิดใช้

1. รัน migration `202610150039_department_transfers_and_support_chat.sql` ใน Supabase
2. ตรวจว่าตารางใหม่เปิด RLS และ `support_chat_messages` อยู่ใน publication `supabase_realtime`
3. ทดสอบบัญชี Staff ส่งข้อความ และทดสอบบัญชีอื่นเห็นข้อความทันที
4. ทดสอบบัญชี Admin/Exec ย้ายพนักงานหนึ่งคน แล้วตรวจประวัติ แผนกปัจจุบัน และข้อมูลย้อนหลัง
5. เมื่อผ่านจึงเผยแพร่ไฟล์หน้าเว็บเวอร์ชันนี้
