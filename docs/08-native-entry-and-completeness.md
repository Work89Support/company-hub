# กรอกข้อมูลผ่าน Company Hub

ข้อมูลกิจกรรมใหม่กรอกที่ “บันทึกกิจกรรม → + บันทึกกิจกรรม” ไม่ต้องใช้ Google Sheets
รายการนำเข้าเดิมยังเก็บไว้ หัวหน้าต้องเลือกบัญชีเจ้าของจริงก่อนพนักงานจะแก้ได้
ระบบไม่จับคู่ชื่อกับบัญชีอัตโนมัติ เพราะชื่ออาจซ้ำกัน

| ผู้ใช้ | กิจกรรม | ปัญหาหน้างาน |
| --- | --- | --- |
| พนักงาน | อ่านและแก้เฉพาะรายการที่ผูกกับบัญชีตนเอง บันทึกในแผนกหลัก | แจ้งใหม่และเติมรายละเอียดเคสที่ตนแจ้ง อ่านเพิ่มเติมตามสิทธิ์แผนกเดิม |
| หัวหน้า | อ่านตามสิทธิ์แผนก แก้และจับคู่เจ้าของเฉพาะแผนกที่มีสิทธิ์จัดการ | เติมรายละเอียด ติดตาม และยืนยันปิดเคสเฉพาะแผนกที่มีสิทธิ์จัดการ |
| ผู้บริหาร / Admin | ดูและจัดการทุกแผนก | ดูและจัดการทุกแผนก |

เมื่อล็อกอิน หากมีข้อมูลไม่ครบ ระบบแจ้งจำนวนที่ต้องเติม พร้อมเมนู “ข้อมูลที่ต้องเติม”
แยก “ของฉัน” กับ “ทีมที่ฉันจัดการ” การรับทราบไม่ลบรายการออกจากคิว
คิวกิจกรรมแสดงครั้งละ 100 รายการ เมื่อเติมแล้วรายการถัดไปจะขึ้นแทน
หัวหน้าควรเริ่มจากรายการเก่าที่ยังไม่ผูกบัญชี เลือกเจ้าของแล้วกด “มอบหมายให้เจ้าของเติมข้อมูล” ได้โดยยังไม่ต้องกรอกรายละเอียดแทนพนักงาน พนักงานจะไม่เห็นรายการเหล่านี้ก่อนจับคู่

## ข้อมูลบังคับ

กิจกรรมทุกสถานะต้องมีแผนก บัญชีเจ้าของ วันที่ กิจกรรม ประเภท และเวลาเริ่ม
“กำลังทำ” ยังไม่ต้องกรอกเวลาจบ “ติดปัญหา” ต้องบอกสิ่งที่ติดขัด
“เสร็จแล้ว” ต้องมีเวลาจบ วันที่เสร็จ และผลลัพธ์ ช่วงเวลาต้องมากกว่า 0 และไม่เกิน 16 ชั่วโมง
งานข้ามคืนต้องเลือกช่องข้ามวันและวันที่เสร็จให้ถูกต้อง
ช่องเว็บ/สถานที่ใช้เมื่อเกี่ยวข้องกับงานนั้นเท่านั้น

การแจ้งปัญหาต้องมีเหตุการณ์ โปรเจกต์ ประเภท ทีมรับผิดชอบ และผลกระทบ
ผู้แจ้งเติมรายละเอียดและหลักฐานของเคสตนเองได้ แต่เปลี่ยนสถานะหรือยืนยันผลไม่ได้
หัวหน้าปิดเคสได้เมื่อมีผลกระทบ ทีมรับผิดชอบ วิธีแก้ ประเภทวิธีแก้ ระยะเวลา และยืนยันว่าทดสอบแล้ว
จำนวนลูกค้า/รายการ/มูลค่าและหลักฐานเพิ่มเติมไม่บังคับเมื่อยังไม่มีข้อมูล

## การคำนวณและประวัติ

ชั่วโมงในโมดูลกิจกรรมนับเฉพาะรายการที่ข้อมูลครบและเวลาผ่านการตรวจ
จำนวนรายการทั้งหมดและจำนวนที่ต้องเติมยังแสดงแยกกัน ไม่ใช่การลบงานเก่า
การแก้กิจกรรมเก็บก่อน/หลัง ผู้แก้และเวลาใน activity_edit_history
ข้อมูลจากชีตเก่ายังคงรหัสอ้างอิงเดิม เมื่อแก้ผ่านระบบ source จะเป็น Company Hub
การบันทึกพร้อมกันใช้ revision ป้องกันทับข้อมูล ส่วนเคสใช้ updated_at

## ติดตั้ง

รัน Migration 020 และ 021 หลัง Migration 019 ก่อนเผยแพร่หน้าเว็บรุ่น native-entry
Migration 020 ถอนสิทธิ์เรียก import_daily_activities และ finalize_daily_activity_sync
จาก authenticated และบังคับเขียนกิจกรรมผ่าน save_activity_entry เท่านั้น
ไม่ได้ลบฟังก์ชันนำเข้า ข้อมูลประวัติ หรือแก้ Google Sheets ต้นฉบับ
ถ้ามีงานนำเข้าภายนอกที่ใช้สิทธิ์เจ้าของฐานข้อมูล ต้องยุติงานนั้นต่างหาก

ทดสอบ:

```sh
node scripts/check-prototype-regressions.mjs
node scripts/check-native-entry.mjs
PGLITE_MODULE=/path/to/@electric-sql/pglite/dist/index.js node scripts/check-native-entry-db.mjs
```

การทดสอบฐานข้อมูลใช้ฐานข้อมูลชั่วคราวและผู้ใช้สมมติ ไม่เขียนข้อมูลทดสอบเข้า Production
