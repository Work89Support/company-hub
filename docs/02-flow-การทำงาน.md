# Flow การทำงานของระบบ (Workflow)

เอกสารนี้อธิบายเส้นทางการทำงานหลักของระบบ พร้อมไดอะแกรม (Mermaid) — เปิดดูใน VS Code (ติดตั้งส่วนขยาย Markdown Preview Mermaid) หรือ GitHub จะเรนเดอร์ให้อัตโนมัติ

---

## 1. Flow ภาพรวม: จากนโยบายผู้บริหาร → งาน → วัดผล

```mermaid
flowchart TD
    A[ผู้บริหารออกนโยบาย/เป้าหมาย] --> B[หัวหน้าแผนกแตกเป็นงาน]
    B --> C{AI Task Composer<br/>จัดรูปงานให้อ่านง่าย}
    C --> D[มอบหมายให้พนักงาน]
    D --> E[พนักงานรับงาน + จับเวลา]
    E --> F{ต้องมอบต่อไหม?}
    F -->|ใช่| G[สร้าง Sub-task มอบให้คนอื่น]
    F -->|ไม่| H[ลงมือทำตาม SOP ที่ผูกกับงาน]
    G --> H
    H --> I[บันทึกวิธีแก้/คำตอบในงาน]
    I --> J[หัวหน้าตรวจ/อนุมัติ → ปิดงาน]
    J --> K[ระบบสร้างบทความ Knowledge Base อัตโนมัติ]
    J --> L[อัปเดตค่า KPI อัตโนมัติ]
    L --> M[Dashboard ผู้บริหาร]
    K --> N[คลังความรู้ค้นหาได้ + ใช้ซ้ำ]
```

## 2. Flow การมอบหมายและตามงาน (ตอบปัญหา "สั่งไปไม่รู้ใครทำ/ใช้เวลาเท่าไหร่")

```mermaid
sequenceDiagram
    participant S as หัวหน้า (สั่งงาน)
    participant SYS as ระบบ Company Hub
    participant E as พนักงาน (ผู้รับงาน)
    participant E2 as พนักงานอีกคน (มอบต่อ)

    S->>SYS: สร้างงาน + ระบุผู้รับผิดชอบ + กำหนดส่ง
    SYS-->>E: แจ้งเตือน (มีงานใหม่)
    E->>SYS: กดรับงาน (สถานะ: กำลังทำ, เริ่มจับเวลา)
    E->>SYS: สร้าง Sub-task มอบต่อให้ E2
    SYS-->>E2: แจ้งเตือนงานย่อย
    E2->>SYS: อัปเดตความคืบหน้า
    Note over SYS: ทุกสถานะถูกบันทึกเวลา (SLA)
    SYS-->>S: เห็นสายงานทั้งหมด + เวลาที่ใช้ ใน Central Feed
    E->>SYS: บันทึกวิธีแก้ + ส่งงาน
    S->>SYS: อนุมัติ/ปิดงาน
```

**ผลลัพธ์:** หัวหน้าและผู้บริหารเห็นตลอดว่า *ใครทำ อยู่สถานะไหน ใช้เวลาไปเท่าไหร่ และค้างที่ขั้นตอนใด* — รวมถึงงานที่ถูกมอบต่อหลายทอด

## 3. Flow วงจร KPI (อ้างอิง Workflow แผนก KPI จริง)

```mermaid
flowchart LR
    P[รับนโยบาย] --> Q[ประชุมแผนก<br/>เก็บหน้าที่/เป้า/ปัญหา]
    Q --> R[ออกแบบ KPI<br/>Target/Weight/รอบวัด]
    R --> S[ทำ Dashboard<br/>ดึงข้อมูลจากงานในระบบ]
    S --> T[ติดตามผล<br/>วัน/สัปดาห์/เดือน]
    T --> U{ต่ำกว่าเป้า?}
    U -->|ใช่| V[วิเคราะห์ Root Cause<br/>สร้าง Action Plan]
    U -->|ไม่| W[รายงานผู้บริหาร]
    V --> W
    W --> P
```

## 4. Flow Talk to Data (ถามข้อมูลภายใน)

```mermaid
flowchart TD
    U[ผู้ใช้พิมพ์คำถามภาษาไทย] --> R{ตรวจสิทธิ์ตาม Role}
    R -->|อนุญาต| Q[AI แปลงคำถามเป็น Query]
    Q --> DB[(ฐานข้อมูลภายในเท่านั้น)]
    DB --> A[ประมวลผล + สร้างกราฟ/ตาราง]
    A --> O[ตอบเป็นภาษาที่เข้าใจง่าย]
    R -->|เกินสิทธิ์| X[ปฏิเสธ + อธิบายขอบเขต]
```

> ข้อสำคัญ: AI ตอบจากฐานข้อมูลของเราเท่านั้น ไม่ดึงข้อมูลภายนอก และจำกัดขอบเขตข้อมูลตามสิทธิ์ของผู้ถาม

## 5. Flow Knowledge Base อัตโนมัติ

```mermaid
flowchart LR
    A[ปิดงานที่มีการบันทึกวิธีแก้] --> B[ดึงปัญหา + วิธีแก้]
    B --> C[AI สรุปให้อ่านง่าย + ตั้งแท็ก]
    C --> D[สร้างบทความในคลังความรู้]
    D --> E[ค้นหา/แนะนำอัตโนมัติ<br/>ตอนสร้างงานคล้ายกัน]
```

## 6. สถานะงานมาตรฐาน (Task Status)

| สถานะ | สี | ความหมาย |
|--------|-----|-----------|
| ยังไม่เริ่ม (To do) | เทา | รับเข้าระบบ ยังไม่มีคนลงมือ |
| กำลังทำ (In progress) | น้ำเงิน | มีผู้รับผิดชอบและเริ่มจับเวลา |
| รอตรวจ/อนุมัติ (Review) | เหลือง/ส้ม | ส่งงานแล้ว รอหัวหน้าตรวจ |
| ติดปัญหา (Blocked) | แดง | ค้าง ต้องการความช่วยเหลือ |
| เสร็จ (Done) | เขียว | อนุมัติและปิดงาน → เข้าสู่ KB/KPI |
