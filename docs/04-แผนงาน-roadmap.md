# แผนงานพัฒนา (Roadmap)

แนวทางจากสถานะปัจจุบัน (ดูรูปแบบ) → ระบบใช้งานจริง

---

## ระยะที่ 0 — Prototype (ตอนนี้) ✅
- ทำ Prototype HTML/CSS/JS คลิกดูได้ทันที (ในโฟลเดอร์ `prototype/`)
- เอกสารออกแบบระบบ + Flow + KPI/SOP
- เปิดใน VS Code → Push ขึ้น GitHub Desktop เพื่อรีวิวร่วมกัน
- **เป้าหมาย:** เห็นภาพ ตกลงขอบเขต และ flow ก่อนลงมือสร้างจริง

## ระยะที่ 1 — วางรากฐาน (สัปดาห์ 1-3)
- ตั้งโปรเจกต์ Next.js + TypeScript + Tailwind + ฟอนต์ Kanit + ธีมน้ำเงิน-ขาว
- ทำระบบ Auth + RBAC (4 ระดับ) และโครงฐานข้อมูล (Prisma + PostgreSQL)
- นำเข้าแผนก/ผู้ใช้/SOP จากไฟล์เดิม

## ระยะที่ 2 — Task Management หลัก (สัปดาห์ 4-7)
- Board / Table / Kanban / Timeline
- สร้างงาน มอบหมาย มอบต่อ (sub-task) จับเวลา SLA แจ้งเตือน
- Central Feed + ประกาศ
- **ปิดจุดปวดข้อ 1 และ 10**

## ระยะที่ 3 — SOP + Knowledge Base (สัปดาห์ 8-10)
- SOP Library + ผูก SOP กับงาน + versioning
- สร้าง Knowledge Base อัตโนมัติจากการปิดงาน + ค้นหา
- **ปิดจุดปวดข้อ 2 และ 4**

## ระยะที่ 4 — KPI Engine + Dashboard (สัปดาห์ 11-13)
- ตั้งค่า KPI ต่อแผนก/คน + คำนวณอัตโนมัติจากงาน + นำเข้า Sheets/Excel
- Dashboard 3 ระดับ (คน/แผนก/บริษัท)
- **ปิดจุดปวดข้อ 3**

## ระยะที่ 5 — AI (สัปดาห์ 14-17)
- AI Task Composer (ช่วยจัดรูปงาน)
- Talk to Data (RAG จากฐานข้อมูลภายในเท่านั้น + จำกัดสิทธิ์)
- **ปิดจุดปวดข้อ 5 และ 6**

## ระยะที่ 6 — เชื่อมต่อ & ขยายผล
- เชื่อม Telegram / Google Drive / Back Office เดิม (แจ้งเตือน + ดึงข้อมูล)
- ปรับจูน KPI จริงกับแต่ละแผนก
- อบรมผู้ใช้ + เปิดใช้เต็มรูปแบบ

---

## ลำดับความสำคัญที่แนะนำ
เริ่มจาก **Task + การตามงาน** (ปัญหาใหญ่สุด) → **SOP/Knowledge** → **KPI** → **AI**
เพราะ AI และ KPI จะแม่นยำก็ต่อเมื่อมีข้อมูลงานไหลเข้าระบบสม่ำเสมอแล้ว
