## 1. ที่มาและเป้าหมาย

ปัจจุบันแต่ละแผนกทำงานแยกเครื่องมือกัน (Trello, Telegram, Google Sheets, Excel, Back Office, ChatGPT) ทำให้ข้อมูลกระจัดกระจาย สั่งงานแล้วตามงานยาก และความรู้/วิธีแก้ปัญหาไม่ถูกเก็บอย่างเป็นระบบ

**เป้าหมายของระบบ** คือสร้าง "ศูนย์รวมข้อมูลของบริษัท" (Company Hub) เปรียบเสมือนห้องสมุดกลาง ที่รวม 4 อย่างไว้ในที่เดียว:

1. **งาน (Tasks)** — สั่งงาน มอบหมาย ติดตามสถานะ และระยะเวลาดำเนินการ
2. **ความรู้ (Knowledge Base)** — วิธีแก้ปัญหาถูกบันทึกจากการตอบกลับในงานจริง
3. **การวัดผล (KPI)** — วัดผลรายแผนก/รายคน เห็นภาพรวมแบบ Dashboard
4. **คู่มือ (SOP)** — คู่มือการปฏิบัติงานของทุกแผนก ดูได้ในระบบ

### ปัญหาหลักที่ระบบต้องแก้ (ตามที่ระบุมา)

| # | ปัญหา | โมดูลที่ตอบโจทย์ |
|---|--------|------------------|
| 1 | สั่งงานไปแล้วไม่รู้ว่าใครทำ และใช้เวลาเท่าไหร่ | Task Management + Assignment + Time Tracking |
| 2 | วิธีแก้ปัญหาไม่ได้ถูกเก็บเป็นคลังความรู้ | Auto Knowledge Base (จากการตอบกลับในงาน) |
| 3 | ต้องวัดด้วย KPI ของแต่ละแผนก | KPI Engine + Dashboard |
| 4 | ต้องมีคู่มือปฏิบัติงาน (SOP) ให้เห็นในระบบ | SOP Library |
| 5 | อยากถามข้อมูลจากฐานข้อมูลเราได้ (Talk to Data) | AI Data Assistant (RAG จากฐานข้อมูลภายในเท่านั้น) |
| 6 | อยากมี AI ช่วยตอนสร้างงานให้อ่านง่าย | AI Task Composer |
| 7 | รูปแบบอ้างอิง Monday | UI/UX แบบ Board + Table + Timeline |
| 8 | ธีมน้ำเงิน-ขาว ฟอนต์ Kanit | Design System |
| 9 | แบ่ง user หลายระดับ | RBAC (Role-Based Access Control) |
| 10 | ผู้รับมอบหมายสั่งงานต่อได้ รวมไว้ที่เดียว | Sub-task / Delegation + Central Feed |

## 2. ผู้ใช้งานและระดับสิทธิ์ (User Roles / RBAC)

ระบบแบ่งมุมมองเป็น 3 ระดับหลักตามที่ต้องการ (พนักงาน → หัวหน้างาน → ผู้บริหาร) และมีระดับเสริมสำหรับดูแลระบบ

| ระดับ | บทบาท | มุมมองหลักที่เห็น | สิทธิ์สำคัญ |
|-------|--------|------------------|-------------|
| **L1 พนักงาน** (Staff) | ผู้ปฏิบัติงาน | งานของฉัน, บอร์ดทีม (เฉพาะที่เกี่ยว), SOP, คลังความรู้ | รับงาน อัปเดตสถานะ ตอบวิธีแก้ ตั้ง sub-task ให้ตัวเอง |
| **L2 หัวหน้างาน** (Supervisor) | หัวหน้าแผนก | บอร์ดทั้งแผนก, KPI แผนก, อนุมัติงาน, จัดคน | สั่งงาน/มอบหมาย มอบต่อ (delegate) อนุมัติ ปิดงาน ดู KPI ทีม |
| **L3 ผู้บริหาร** (Executive) | ผู้บริหาร/เจ้าของ | KPI ภาพรวมทุกแผนก, ประกาศ, รายงานสรุป, Talk to Data | ออกนโยบาย ดูทุกแผนก อนุมัติงานข้ามแผนก ดูรายงานเชิงลึก |
| **L0 Admin ระบบ** | ทีม KPI / IT | จัดการผู้ใช้ แผนก สิทธิ์ ตั้งค่า KPI/SOP | ตั้งค่าระบบทั้งหมด |

**หลักการมองเห็นข้อมูล (Data Visibility):**
- พนักงานเห็นเฉพาะงานของตนและงานในทีม
- หัวหน้าเห็นทั้งแผนกของตน + งานที่ตนสั่งข้ามแผนก
- ผู้บริหารเห็นทุกแผนก (read-all) และเจาะดูรายละเอียดได้
- ทุกการมอบหมาย/มอบต่อ ถูกรวมไว้ใน "Central Feed" เพื่อให้ตามงานได้จากที่เดียว

## 3. โครงสร้างองค์กรที่รองรับ (จากไฟล์ KPI/SOP จริง)

ระบบตั้งต้นด้วยแผนกจริงของบริษัท ดังนี้

| รหัส | แผนก | งานหลักโดยสรุป |
|------|------|----------------|
| KPI | แผนก KPI | กำหนด/ควบคุม/วิเคราะห์ตัวชี้วัด ทำ Dashboard รายงานผู้บริหาร ตรวจ SOP |
| MKT | การตลาด | วางกลยุทธ์แบรนด์ ทำคอนเทนต์/แคมเปญ วิเคราะห์พฤติกรรมลูกค้า |
| GRAPHIC | กราฟิก | ออกแบบสื่อ แบนเนอร์ ภาพโปรโมชั่น ตัดต่อวิดีโอ |
| CRM | ลูกค้าสัมพันธ์ | โทรดูแลลูกค้า รักษาฐานลูกค้า (retention) ทำ realtime |
| ADMIN | แอดมิน | ตอบแชท ดูแลลูกค้าหน้างาน ประสานงาน |
| QC-BC | QC Chat & Back Office | ตรวจคุณภาพการตอบแชท ดูแลบัญชี/นายหน้า รับ-ส่งพัสดุ |
| FIN | การเงิน | เบิกจ่าย อนุมัติยอด ทำสรุปรายเดือน กระทบยอด |
| BO | Back Office Management | ดูภาพรวมหน้างาน อนุมัติ วิเคราะห์ปัญหา ติดตามงาน |

> โครงสร้าง SOP ของทุกแผนกเป็นรูปแบบเดียวกัน (หน้าที่ → Workflow → งานประจำ → เครื่องมือ → จุดตรวจด้วยคน → ปัญหาที่พบ → งานที่ AI ช่วยได้ → ข้อเสนอแนะพัฒนา) จึงนำมาทำเป็น "เทมเพลต SOP มาตรฐาน" ในระบบได้ทันที

## 4. โมดูลของระบบ (System Modules)

### 4.1 Task Management (หัวใจของระบบ)
- โครงสร้าง: **Workspace → Board (แผนก) → Group (สถานะ/โปรเจกต์) → Item (งาน) → Sub-item (งานย่อย)**
- ฟิลด์งานมาตรฐาน: ผู้สั่งงาน, ผู้รับผิดชอบ, ผู้ติดตาม, สถานะ, ความสำคัญ, วันเริ่ม-กำหนดส่ง, เวลาที่ใช้จริง (Time Tracking), แท็ก/หมวด, ไฟล์แนบ, เชื่อมโยง SOP
- **การแท็กงาน (Tagging):** แท็กแผนก / ประเภทงาน / ปัญหา / SOP อ้างอิง ใช้ค้นหาและทำรายงาน
- **มอบหมายต่อ (Delegation):** ผู้รับงานสามารถสร้าง sub-task มอบให้คนอื่นต่อ โดยงานต้นทางยังเห็นสายงานทั้งหมด (traceability)
- **SLA / ระยะเวลา:** ระบบจับเวลาแต่ละสถานะ แจ้งเตือนเมื่อใกล้/เกินกำหนด → ตอบปัญหา "สั่งงานไปไม่รู้ใครทำ/ใช้เวลาเท่าไหร่"

### 4.2 มุมมอง (Views แบบ Monday)
- **Table View** — ตารางงานแบบ spreadsheet (ค่าเริ่มต้น)
- **Kanban View** — การ์ดตามสถานะ
- **Timeline / Gantt** — ดูภาระงานและ deadline
- **Calendar View** — ปฏิทินกำหนดส่ง
- **Dashboard View** — สรุปตัวเลข/กราฟ

### 4.3 Knowledge Base (คลังความรู้อัตโนมัติ)
- เมื่อปิดงาน ระบบดึง "วิธีแก้ปัญหา / คำตอบ" ที่บันทึกในงาน มาสร้างเป็นบทความความรู้อัตโนมัติ พร้อมแท็กแผนก/ประเภทปัญหา
- ค้นหาได้ + AI ช่วยสรุปให้อ่านง่าย → กลายเป็น "ห้องสมุดวิธีแก้ปัญหา" ของบริษัท
- ป้องกันการตอบคำถามซ้ำ: ตอนสร้างงานใหม่ ระบบแนะนำบทความที่เคยแก้ปัญหาคล้ายกัน

### 4.4 KPI Engine + Dashboard
- ตั้งค่า KPI ต่อแผนก/ตำแหน่ง: ชื่อตัวชี้วัด, เป้าหมาย (Target), น้ำหนัก (Weight), รอบวัด (วัน/สัปดาห์/เดือน), วิธีคิดคะแนน
- ดึงค่าจริงได้จาก: ข้อมูลงานในระบบ (อัตโนมัติ) หรือกรอกมือ/นำเข้าจาก Google Sheets/Excel
- Dashboard 3 ระดับ: รายคน → รายแผนก → ภาพรวมบริษัท พร้อมสถานะสี (สูงกว่า/ตามเป้า/ต่ำกว่า) และแนวโน้ม

### 4.5 SOP Library (คู่มือปฏิบัติงาน)
- เก็บ SOP ทุกแผนกในรูปแบบมาตรฐานเดียวกัน มีเวอร์ชัน (versioning) และผู้อนุมัติ
- ผูก SOP เข้ากับงาน: เปิดงานประเภทไหน เห็นขั้นตอนที่ต้องทำทันที
- ติดตามการปฏิบัติตาม SOP (compliance) เป็นส่วนหนึ่งของ KPI

### 4.6 Talk to Data (AI ถามข้อมูลภายใน)
- ผู้ใช้พิมพ์ถามภาษาไทย เช่น "เดือนนี้ CRM ปิดงานกี่งาน", "งานค้างเกินกำหนดของกราฟิกมีอะไรบ้าง"
- AI แปลงเป็น query → ดึงจาก **ฐานข้อมูลภายในของเราเท่านั้น** (ไม่ออกอินเทอร์เน็ต) → ตอบพร้อมกราฟ/ตาราง
- จำกัดสิทธิ์ตาม Role (พนักงานถามได้เฉพาะขอบเขตข้อมูลตน)

### 4.7 AI Task Composer (ช่วยสร้างงานให้อ่านง่าย)
- พิมพ์สั่งงานแบบสั้น ๆ → AI จัดรูปเป็นงานที่ชัดเจน: หัวข้อ, รายละเอียด, ขั้นตอนย่อย (checklist), ผู้รับผิดชอบที่แนะนำ, กำหนดส่งที่เหมาะสม, SOP/บทความที่เกี่ยวข้อง

### 4.8 ประกาศ & บอร์ดอัปเดต (Announcements / Central Feed)
- บอร์ดประกาศจากผู้บริหาร/หัวหน้า + ฟีดอัปเดตงานรวมทุกแผนก
- คือ "บอร์ดกลาง" ที่ทุกคนอัปเดตงานและเห็นความเคลื่อนไหวได้จากที่เดียว

## 5. สถาปัตยกรรมทางเทคนิค (สำหรับสร้างจริงในอนาคต)

ออกแบบให้สอดคล้องกับ **React / Next.js** ตามที่วางแผนไว้

```
Frontend  : Next.js (App Router) + React + TypeScript + Tailwind CSS
            ฟอนต์ Kanit (next/font) ธีมน้ำเงิน-ขาว ผ่าน CSS variables
UI/Comp   : shadcn/ui หรือ component library + ตาราง/บอร์ดแบบ Monday
State/Data : TanStack Query + tRPC หรือ REST
Backend   : Next.js API Routes / Node (NestJS ถ้าต้องแยก service)
Database  : PostgreSQL (Prisma ORM)  + Redis (cache/queue)
Realtime  : WebSocket / Pusher / Supabase Realtime (อัปเดตบอร์ดสด)
Auth      : NextAuth / Clerk + RBAC ตาม role
AI Layer  : LLM API + RAG (pgvector) จำกัดข้อมูลจาก DB ภายในเท่านั้น
Files     : S3-compatible storage
Deploy    : Vercel / Docker (ตามนโยบายบริษัท)
```

**หลักการ:** ตอนนี้ทำ Prototype เป็น HTML/CSS/JS ล้วน (เปิดดูได้ทันที ไม่ต้อง build) เพื่อเห็นรูปแบบและ flow ก่อน แล้วค่อยยกโครงหน้าจอ/คอมโพเนนต์ไปทำเป็น Next.js ตามสถาปัตยกรรมข้างบน

## 6. โมเดลข้อมูลหลัก (Core Data Model — ย่อ)

```
User(id, name, email, role[L0-L3], departmentId, avatar)
Department(id, code, name, headUserId)
Board(id, departmentId, name)
Task(id, boardId, title, description, status, priority,
     ownerId, assigneeId, creatorId, parentTaskId,
     startDate, dueDate, timeSpent, tags[], sopId, createdAt)
TaskUpdate(id, taskId, userId, type[comment|status|solution], body, createdAt)
KnowledgeArticle(id, sourceTaskId, title, problem, solution, tags[], departmentId)
KPI(id, departmentId|userId, name, target, weight, period, formula)
KPIRecord(id, kpiId, period, actual, score)
SOP(id, departmentId, title, version, sections[], approvedBy, status)
Announcement(id, authorId, title, body, audience, pinned, createdAt)
```
